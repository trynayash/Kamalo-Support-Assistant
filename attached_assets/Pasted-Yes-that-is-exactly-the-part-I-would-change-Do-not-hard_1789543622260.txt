### And I would make one more important change

Your current prompt says:

> “The initial registry contains knowledge retrieval plus clearly synthetic, read-only demo tools for customer, transaction, Coins, commission, and FINCADO-style support examples.”

That's good, but make the demo boundary **extremely explicit**, because otherwise an agent may accidentally make those fake tools look like real KAMALO data.

Use:

```text
Demo tools MUST be namespaced and visibly identified internally as synthetic.

Example:

demo.customer.get
demo.transaction.get
demo.coins.getBalance
demo.commission.get
demo.fincado.getProgress

Never name them:

customer.get
transaction.get
coins.getBalance

because those names imply live KAMALO authority.

The demo providers must return metadata such as:

{
  sourceType: "demo",
  synthetic: true
}

The orchestrator and response validator must know that synthetic results are not production account truth.

The user-facing assistant must never imply that demo data represents the user's actual KAMALO account.
```

That makes your eventual migration much cleaner:

```text
TODAY

demo.coins.getBalance
        ↓
DemoCoinProvider


LATER

kamalo.coins.getBalance
        ↓
KamaloCoinProvider
        ↓
Real KAMALO API
```
